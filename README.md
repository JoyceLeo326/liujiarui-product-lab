# Joyce · 产品实验室

![Joyce 的产品实验室：从具体的人出发，把不同问题做成可验证的产品](docs/readme-hero.png)

**不是把项目排成一列，是把每个问题真正做完。**

有时是一顿四人午餐：有人想吃辣，有人忌口，预算和距离也不一样。有时是一位老师站在资源有限的教室里，想把明天的课讲得更好。也有时，是一次不能含糊的康复记录——今天做了什么、哪里不舒服、下一步该不该继续。

先看见具体的人，再把没说清的冲突摊开，做成可以选择、执行和回看的产品。

每个项目先交代谁遇到了什么，再说产品如何选择、执行与复核；能在线体验的直接给入口，需要保留研究边界的则把证据和源码可见性说清楚。

[在线浏览产品实验室](https://joyceleo326.github.io/joyce-product-lab/)

## 十一个产品，不是同一种解法

一顿饭需要让四个人真正达成一致；一堂课要能在明天的教室里落地；一份康复记录既要连续，也要在风险出现时及时停下来。它们没有共用一套漂亮模板，而是共用一条朴素的工作方法：进入现场，看清限制，把选择交还给人，再留下可以执行和复核的结果。

首页给了四条浏览路径：想看作品有没有做完、问题有什么不同、能不能马上使用，或怎样一起协作。选择不同路径只会改变项目出现的先后，不会改变项目的状态和边界。

## 使用方式

1. 从首页选择“招聘者、评审者、真实用户、合作者”之一。
2. 阅读每个项目的“此刻、冲突、带走”三段故事，快速理解用户与产品结果。
3. 通过“进入产品”完成真实核心流程，直接看到输入、选择与结果如何变化。
4. 对公开项目可继续查看 GitHub 源码、提交与发布记录。
5. 改变观察视角，比较同一组作品在不同判断目标下的优先级。

## 当前收录

这里目前收着 11 个可以进入和使用的产品，覆盖：

- 多人点餐决策与公平协商；
- 文献研究和可追溯交付；
- 城市路线选择与约束说明；
- 教学资源、康复记录和学习交付；
- 视频工作流、故事改编和跨文化表达；
- 翻译、饮品创新与人机协作研究。

每个条目都维护角色、阶段、故事、标签、体验地址和源码可见性。私人学习与个人材料不进入这个公开目录，也不通过本站提供镜像或入口。

## 站点特性

- **按关心的问题浏览**：从完成度、差异、直接体验或协作边界进入，而不是被固定时间线牵着走。
- **故事化项目卡**：每项都说明具体人物、真实冲突与可带走结果。
- **真实性边界**：公开源码、私有源码、研究记录和线上产品分开表达。
- **私有产品镜像**：路线规划与乡村教师只发布经过安全门禁的静态产品产物，源码仓库和历史仍保持私有。
- **零构建运行**：原生 HTML、CSS 与 JavaScript，无框架运行时。
- **离线支持**：同源静态资源由 Service Worker 缓存；首次访问仍需要网络。
- **可访问性**：提供跳过链接、语义化区域、键盘可操作按钮与状态播报。

## 本地运行

需要 Node.js 18 或更高版本。站点没有构建步骤，请通过静态服务器访问：

```bash
npx serve .
```

也可以使用其他能正确提供 JSON、Web Manifest 和 Service Worker 的静态服务器。不要直接双击 `index.html`，否则浏览器可能限制 `fetch('./projects.json')`。

## 验证

```bash
npm test
npm run check
```

`npm run check` 会运行 Node 测试，并对 `app.js` 与 `sw.js` 执行语法检查。测试覆盖项目数据契约、角色筛选、公开/私有链接规则和核心页面结构。

## 更新一个项目

编辑 `projects.json` 中的对应条目，并确保：

1. `status` 真实区分 `live` 与 `research`；
2. `roles` 至少包含一个支持的观察视角；
3. `story.person`、`story.conflict`、`story.outcome` 均有事实依据；
4. `sourceVisibility` 与 GitHub 当前可见性一致；
5. 私有仓库不填写公开源码入口；
6. 体验地址只指向真实可访问或仓库内已有的镜像。

修改后运行 `npm run check`，再通过浏览器分别切换四个视角核对排序和链接。

## 部署

`main` 分支通过测试和敏感信息门禁后，由 `.github/workflows/` 中的工作流发布到 GitHub Pages。站点使用相对路径，字体、脚本、样式、图标、Manifest 与项目数据都随仓库部署，不依赖第三方 CDN。

## 目录

```text
.
├─ index.html                 # 页面结构与四种观察视角
├─ styles.css                # 响应式视觉和交互状态
├─ app.js                    # 数据加载、角色排序与卡片渲染
├─ projects.json             # 十一个公开产品的资料卡与入口
├─ sw.js                     # 同源静态资源缓存
├─ manifest.webmanifest      # PWA 元数据
├─ favicon.svg               # 本地品牌图标
├─ docs/readme-hero.png      # README 头图
├─ products/route/           # 路线规划的安全静态产品镜像
├─ products/rural/           # 乡村教师的安全静态产品镜像
├─ products/mirror-manifest.json # 镜像来源指纹与脱敏门禁摘要
├─ tests/                    # 数据与页面契约测试
└─ .github/workflows/        # 验证与 Pages 发布
```

## 隐私与局限

- 站点只读取同源静态内容，不提交表单、不加载分析脚本，也不调用远程 AI。
- 浏览项目会请求仓库内的 `projects.json` 和同源静态资源，不收集 API Key。
- Service Worker 缓存可通过浏览器“清除站点数据”删除。
- 每个项目的状态和入口都来自仓库内的资料卡；未公开的私人材料不会出现在目录中。
- 私有项目只展示经过安全检查的静态产品镜像，不公开源码、提交历史或敏感配置。
- `products/mirror-manifest.json` 只保存不可逆的来源提交指纹、产物摘要与当前树/产物扫描结果；CI 会重算文件数和摘要，不包含源码历史、历史候选数量或凭据内容。
- 外部产品入口由各自平台独立托管，长期可达性不能由本目录站点保证。
